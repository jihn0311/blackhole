# EVENT HORIZON · 이벤트 호라이즌

**천체를 공급해 블랙홀을 성장시키고, 플레이어의 행동에 따라 서로 다른 결말을 만나는 PC 웹 게임입니다.**

[게임 플레이](https://jihn0311.github.io/blackhole/) · [관리자 로그인](https://blackhole-bxhq.onrender.com/?admin)

## 작품 소개

태양계를 위협하는 블랙홀 앞에 파견된 주인공은 첨단 합성 장치로 인공 천체를 공급합니다. 천체를 흡수시키며 질량을 늘리고, 강화와 환생을 통해 성장하면서 네 가지 기본 엔딩을 발견합니다.

성장과 수집뿐 아니라 스토리, 화면 연출, 음악을 함께 경험하도록 기획했습니다. 배포 후에도 천체·엔딩·난이도를 조정할 수 있는 관리자 페이지를 제공합니다.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 스토리와 튜토리얼 | 8장면 도입부 만화와 첫 소환 → 흡수 → 레벨업 → 업그레이드 단계별 안내 |
| 천체 소환·흡수 | 클릭이나 단축키로 천체를 소환하고, 블랙홀에 흡수되면 질량과 경험을 축적 |
| 성장과 미션 | 질량에 따른 레벨업, 천체 해금, 미션·반복 탐사 보상 |
| 스킬 트리 | 일반 강화 80개, 선행 조건에 따른 해금, 확대·축소, 일괄 강화 |
| 자동 생성 | 일반 강화 40개부터 1초마다 천체별 쿨타임 확인, 60개부터 개별 쿨타임에 맞춰 생성 |
| 도감 | 기본 천체 15종과 관리자가 추가한 천체의 정보·발견 기록 확인 |
| 환생 | 일반 강화 완료 후 조건을 달성하면 환생하고 특이점 조각으로 영구 강화 |
| 엔딩 | 일반·변환자(치트)·생존자·The Last Ending과 엔딩별 연출·음악 |
| 질량 랭킹 | 엔딩 수집 조건 달성 후 전체 플레이어의 역대 최고 질량 조회·등록 |
| 자동 저장 | 같은 브라우저와 사이트에서 진행 상황을 저장하고 이어서 플레이 |
| 관리자 페이지 | 게임 설정 검토, 천체 추가·수정·삭제, 기본·추가 엔딩 관리와 공개 배포 |

수치와 해금 조건은 관리자가 변경할 수 있습니다. 위 천체 수는 기본 콘텐츠 기준이며, 추가 콘텐츠에 따라 실제 목록 수가 달라집니다.

## 플레이 방법

1. 도입부와 튜토리얼로 임무와 조작법을 확인합니다. 튜토리얼은 도감에서 다시 볼 수 있습니다.
2. 천체 버튼 또는 단축키로 소환합니다. 선택한 천체는 우주 공간을 클릭해서도 소환할 수 있습니다.
3. 천체가 흡수되면 질량이 증가합니다. 레벨업·미션 보상으로 스킬을 강화합니다.
4. 새로운 천체를 발견하고, 자동 생성과 환생을 활용하며 엔딩을 탐색합니다.

**소환 위치는 마우스 위치가 아닌 우주 공간 가장자리입니다.** 해금되지 않았거나 쿨타임이 남은 천체는 소환할 수 없습니다.

| 단축키 | 천체 | 단축키 | 천체 |
| --- | --- | --- | --- |
| 1 | 소행성 | 7 | 지구 |
| 2 | 명왕성 | 8 | 천왕성 |
| 3 | 달 | 9 | 토성 |
| 4 | 수성 | 0 | 해왕성 |
| 5 | 화성 | - | 목성 |
| 6 | 금성 | = | 태양 |
| Q | 적색거성 | W | 백색왜성 |
| E | 중성자별 | | |

- 좌우 패널은 화살표로 접고 펼칠 수 있으며, 새 천체 해금·미션 달성은 빨간 점으로 알립니다.
- 소리와 효과음 설정, 일시정지 등은 질량·미션 패널 아래에서 이용합니다.
- 크레딧에서는 스페이스바를 누르고 있으면 진행이 빨라집니다.
- M·R과 천체별 질량은 게임용 수치입니다. 실제 천체 설명은 도감의 NASA 출처를 참고합니다.

## 관리자와 배포 흐름

공개 게임의 관리자 버튼은 별도 Render 서버의 로그인 화면으로 연결됩니다.

```text
관리자 로그인 → 설정 수정 → 변경 검토 → 배포 확인
→ GitHub의 src/gameSettings.json 저장
→ GitHub Actions 테스트·빌드 → GitHub Pages 반영
```

- 천체의 질량·쿨타임·해금 조건과 게임 성장 배율을 수정할 수 있습니다.
- 기본 천체 삭제·복원과 추가 천체 생성, 기본 엔딩 조건 수정·비활성화, 추가 엔딩 생성·삭제를 지원합니다.
- 서버에서 로그인과 설정을 검증하며, GitHub 파일 버전(SHA)을 비교해 다른 변경을 덮어쓰지 않도록 합니다.
- 배포 API는 지정된 게임 설정 파일만 수정합니다. 비밀번호와 GitHub 토큰은 서버 환경 변수로 관리합니다.
- 변경 사항은 배포 완료 후 게임을 새로고침하면 적용됩니다. 기존 진행 기록은 유지되지만 새 규칙에 따라 레벨·해금 상태가 달라질 수 있습니다.

### 서버 환경 변수

| 변수 | 용도 |
| --- | --- |
| `ADMIN_PASSWORD` | 관리자 비밀번호(9자 이상) |
| `BLACKHOLE_GITHUB_TOKEN` | 대상 저장소 Contents 읽기·쓰기, Actions 읽기 권한 |
| `RENDER_EXTERNAL_URL` 또는 `ADMIN_PUBLIC_URL` | 관리자 서버의 HTTPS 주소 |
| `SUPABASE_URL` | 랭킹 데이터베이스 프로젝트 주소 |
| `SUPABASE_SECRET_KEY` | 서버에서만 사용하는 Supabase 비밀 키 |
| `PORT` | 서버 포트(기본 10000) |

비밀번호와 비밀 키는 저장소나 프런트엔드에 넣지 않습니다. 랭킹 테이블과 함수는 [`database/rankings.sql`](database/rankings.sql)을 참고하세요.

랭킹용 최고 질량은 치트 사용 회차의 질량과 구분하여 기록합니다. 서버는 입력 형식과 등록 간격을 검사하지만, 클라이언트에서 제출하는 기록이므로 완전한 부정행위 방지 시스템은 아닙니다.

## 로컬 실행

Node.js 22를 기준으로 사용합니다(GitHub Actions와 동일).

```sh
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소로 접속합니다. 기본 주소는 `http://127.0.0.1:5173/`입니다.

```sh
npm test          # 게임 규칙 및 관련 동작 테스트
npm run build    # dist/에 배포 파일 생성
npm run preview  # 빌드 결과 미리보기
```

관리자 개발 화면은 로컬 주소의 `?admin`, 내 기록 테스트 화면은 `?admin=save`에서 확인합니다. 내 기록 테스트 화면은 개발 모드 전용이며 해당 주소의 브라우저 저장 기록을 편집합니다.

관리자 서버는 환경 변수를 설정하고 빌드한 뒤 실행합니다.

```sh
npm run build
npm start
```

`main` 브랜치에 변경 사항을 푸시하면 GitHub Actions가 테스트·빌드 후 Pages에 배포합니다. 관리자 서버 상태는 `/healthz`에서 확인할 수 있습니다.
